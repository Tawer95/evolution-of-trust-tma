Phase 4 pipeline. Реализует код по последнему плану в `docs/plans/`.

Опционально override slug: $ARGUMENTS

## Что делать

1. Прочитай последний (или указанный) план `docs/plans/<slug>.md`. Verify: ветка ≠ main.

2. Декомпозируй план на atomic steps. TaskCreate для tracking — обязательно. **Багфикс → первый step всегда «repro-тест»** (падающий тест/manual-репро; фикс готов, когда зелёный, регресс не тронут).

3. Для каждого step:
   - Прочитай затрагиваемые файлы.
   - Внеси изменение через Edit/Write. **Фронт: правки игрового движка (`js/core|sims|slides|lib`) — только если план это явно требует и обосновывает; иначе весь наш код в `js/telegram/`.**
   - **Прогони per-step проверку из плана** (команда/тест/grep + ожидаемый результат). Без неё step не закрывается — «выглядит правильно» не считается.
   - Hooks автоматически: PreToolUse git-guard.
   - Mark step completed.
   - **Bounded self-heal (1 попытка):** упал механический gate (ruff/format, pyright type, F401-import, eslint, тривиальная None-защита) → пофикси **один раз** и перепрогони. Зелёный → дальше. Всё ещё красный ИЛИ фейл нетривиальный (логика, схема БД, **integrity-path: initData/лидерборд-score/save прогресса**) → **STOP + report**, не зацикливай авто-фиксы.

4. **Deferred decision queue** (orchestrate.md → Батчинг): незапланированная развилка T1/T3, не блокирующая остальное → отложи step, продолжай независимые, вопросы в батч в конце фазы. Немедленный STOP без очереди: T2 breaking change, integrity-path, развилка блокирует всё.

5. **Checkpoint commits на ветке** каждые 3-5 steps: `git add <файлы этих steps> && git commit -m "wip: <step>"`. Стейджинг селективный (git-guard блокирует `-A`/`.`). Локальные commits, НЕ push.

6. По завершении (+ разбор deferred-батча) — НЕ финальный commit, НЕ push. Сообщи: «implementation complete, дальше → `/review`».

## Принципы
- Маленькие функции, конструктор-стиль (CLAUDE.md → Конвенции).
- **Root cause, не заплатка:** временная заплатка — только с явным ок юзера + TODO с условием снятия.
- **Анти-регресс оригинала:** не ломай игровой движок ради фичи — цепляйся к pub/sub-событиям (см. CODE-MAP → seams).
- **Scope discipline T1 / Breaking change T2 / Architectural pivot T3** — см. orchestrate.md. Не фикси молча, не выбирай тихо.
- **Source discipline:** перед Edit/Write чужого файла — Read его первым (функция/поле/событие существуют). Дефолты из плана применяй без вопросов.
- План оказался неверен (событие/функция не существует) → STOP, верни юзеру, попроси /plan уточнить.
- **Никогда не push и не создавай PR в /implement.**
